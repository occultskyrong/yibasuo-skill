01 工作流全景

6 阶段线性管道，每阶段有明确门禁。自动模式下阶段 1-4 连续执行。

⚡ 自动模式：阶段 0 确认 → 1-4 连续 → 5 确认
🖐 交互模式：每阶段逐一确认
阶段 0
需求确认
  • 研究复用
  • 头脑风暴
  • 2-3 方案
  • 需求卡片
门禁：需求卡片
含标题+类型+范围+验收≥1
→
阶段 1
规划
  • CodeGraph
  • planner agent
  • 任务分解
  • 风险列表
门禁：任务 ≥ 2
风险点 ≥ 1
→
阶段 2
架构
  • architect agent
  • ADR 决策记录
  • 接口契约
  • 3-5 轮自检
门禁：P0 清零
（5 轮未清零 → 暂停）
→
阶段 3
TDD 开发
  • tdd-guide agent
  • RED → GREEN
  • → IMPROVE
  • 覆盖率报告
门禁：覆盖率 ≥ 80%
所有测试通过
→
阶段 4
审查
  • ESLint 自动检测
  • reviewer ×2
  • 规范逐条核对
  • 基础设施审查
门禁：CRITICAL = 0
且 HIGH = 0（3-5 轮）
→
阶段 5
提交
  • 启动验证
  • 格式复核
  • 构建验证
  • commit + tag
门禁：两种模式
都必须确认提交

02 TDD 循环

阶段 3 核心机制：先写失败测试 → 最小实现 → 重构优化 → 覆盖率门禁

RED
写失败测试
定义预期行为
→
GREEN
最小实现
让测试通过
→
IMPROVE
重构优化
消除重复
覆盖率 ≥ 80% 且所有测试通过 → 进入阶段 4 审查
未达标 → 补测试，继续 RED 循环

03 审查循环

阶段 4 每轮审查：ESLint 先行 → agent 并行 → 规范核对 → 修复后重跑。即使全部通过也跑满 3 轮。

①
ESLint
--max-warnings 0
Error = CRITICAL
自动检测
②
Agent 审查
java-reviewer
ts-reviewer
security-reviewer
③
规范核对
api-response
table-structure
coding-style
logging…
④
输出清单
CRITICAL → HIGH
→ MEDIUM → LOW
按规范分组
⑤
用户确认
暂停等待
用户选择
修复范围
⑥
修复 + 重跑
CRITICAL 必修
HIGH 默认修
重跑 ESLint
⑦
下一轮
重新执行
① - ⑥
至少跑满 3 轮
3-5 Round Loop 即使 0 问题也跑满 3 轮 5 轮后仍有 CRITICAL/HIGH → 暂停 门禁：CRITICAL = 0 && HIGH = 0
