# 前端开发规范

> 一把梭阶段 0 确认需求后，按此规范分流和执行。

## 一、场景路由

不同项目类型对应不同技能路径。**先分流，再动手。**

| 项目类型 | 主技能 | 辅技能 |
|---------|--------|--------|
| 着陆页 / 营销站 / 作品集 | `taste-skill` | `imagegen-frontend-web` |
| 仪表盘 / 后台 / 数据面板 | `ui-ux-pro-max` | `frontend-patterns` |
| 通用页面 / 原型 / 组件 | `frontend-design` | `frontend-patterns` |

## 二、标准流程（6 步 + 迭代内环）

### 0. 需求确认 + 场景路由（必须）

输出设计读数：项目类型 / 目标用户 / 情绪基调 / 技术约束。确认后按上表选择技能路径。一把梭阶段 0 绑定。

### 1. 确认设计方向（新增页面时必须，组件修改可跳过）

调用 `imagegen-frontend-web` 为每个核心页面/模块生成设计参考图。图片工具不可用时降级为 `taste-skill` Section 0 "Design Read" 纯文本方向确认。

### 2. 生成完整 UI 代码（必须）

按场景路由选择主技能调用：
- 着陆页/营销站 → `taste-skill`
- 仪表盘/后台 → `ui-ux-pro-max`
- 通用页面 → `frontend-design`
- 品牌项目 → 先跑 `brandkit` 出 VI 再进入此步
- 改版项目 → `redesign-skill` 替代新建流程

### 3. 设计审查（必须）

调用 `impeccable`：**至少运行 audit**（27 项反模式扫描）。用户可直接感知的核心页面额外运行 critique 和 polish。审查深度与改动影响面成正比。

### ↻ 迭代回退（循环）

`impeccable audit` 不通过时，polish 只能做微调——结构性问题、风格一致性、布局缺陷必须回到步骤 2 重写。**每个核心页面最多迭代 3 轮**，超过则暂停等用户决断。

### 4. 浏览器验证（必须）

用真实浏览器截图验证渲染效果。调用 `verify` 或 `browser-qa`。对比设计参考图和实际页面，确认移动端表现。一把梭阶段 4 末尾执行。

## 三、技能清单

| 技能 | 角色 | 场景 |
|------|:--:|------|
| `taste-skill` | 主 | 着陆页/营销站/作品集 |
| `ui-ux-pro-max` | 主 | 仪表盘/后台/数据面板 |
| `frontend-design` | 主 | 通用页面/原型/组件 |
| `impeccable` | 主 | audit → critique → polish |
| `imagegen-frontend-web` | 辅 | 设计参考图（Web） |
| `imagegen-frontend-mobile` | 辅 | 设计参考图（移动端） |
| `frontend-patterns` | 辅 | 框架细节（路由/状态） |
| `redesign-skill` | 辅 | 存量页面改版升级 |
| `brandkit` | 辅 | 品牌 VI/Logo |
| `design-system` | 辅 | 设计系统生成与审计 |

## 四、铁律（分级门禁）

| # | 规则 | 级别 |
|---|------|:--:|
| 1 | **场景路由是入口** — 任何前端任务必须确认场景类型，不允许不做分流直接写代码 | T1 |
| 2 | **审查不可跳过** — 任何代码变更必须跑 impeccable audit | T1 |
| 3 | **audit 不通过 = 回退重写** — polish 只处理微调，结构/风格/布局问题必须回到步骤 2 | T1 |
| 4 | **output-skill 全程开启** — 禁止截断和占位符，属前置环境配置 | T1 |
| 5 | **新增页面先确认方向** — 设计图或设计读数二选一。组件修改/样式微调/bug 修复可跳过 | T2 |
| 6 | **浏览器验证闭环** — 每个核心页面必须经过浏览器截图验证 | T2 |
| 7 | **改版走 redesign-skill** — 已上线页面改版走审计+设计升级 | T2 |
| 8 | **迭代有上限** — audit→回退→重写最多 3 轮，超过暂停等用户决断 | T3 |

> T1 = 阻断（违反必须退回） · T2 = 建议（有理由可豁免） · T3 = 约束（防无限循环）

---

## 与标准流程的差异

| 标准流程 | 前端流程 |
|---------|---------|
| 阶段 1 规划 | 步骤 0 场景路由 |
| 阶段 2 架构 | 步骤 1 设计方向确认 |
| 阶段 3 TDD | 步骤 2 生成 UI 代码 |
| 阶段 4 审查 | 步骤 3 设计审查（impeccable audit）+ ↻ 回退迭代 + 步骤 4 浏览器验证 |
| 阶段 5 提交 | 同标准流程（prettier+eslint+Lighthouse+备案） |
